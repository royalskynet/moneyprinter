# 以 MoneyPrinterTurbo 為底重建短影音流程：取捨清單

本文件是 2026-11-09 收掉舊流程（自建 2.6G 管線）後的第一版重建計畫。舊流程的完整檢討在 OpenBot 的 `marketer-lessons-2026-11-09.md`，這份只寫「用這個 repo 要怎麼做」。

## 一、為什麼用它

- MIT 授權，可商用可改；14 萬星，維護活躍（最近一次 push 2026-11-07）。
- 已經有：主題／關鍵詞 → 文案 → 素材（Pexels／Pixabay／Coverr 免費）→ 字幕 → 配音 → 合成 → 直式輸出，這正好是舊流程花最多工的地方。
- 支援多家 LLM（OpenAI／Claude／Gemini／DeepSeek／Qwen／Kimi 等），可用免費或訂閱層，不必綁定付費 API。

## 二、必須改掉的三件事（照舊流程踩過的坑）

1. **配音不能用預設 Edge TTS**。Edge TTS 走微軟線上朗讀、用的是微軟商用聲音，拿去經營營利帳號有授權風險；舊流程已因此否決過。改成 Kokoro（Apache-2.0，repo 已內建）或本機 Qwen3-TTS；台灣口音優先，聲音一旦選定要固定範本，避免每支片換人。
2. **選題不能靠「熱門關鍵詞」自動生成**。舊流程實測：從新聞／趨勢檔選題會離題、片內沒有鉤子。要保留「先找同題已爆的片 → 拆前 3 秒鉤子與結構 → 照格式重做」，題材一次最多排 2 支同系列。
3. **文案不能只交給一個模型一次寫完**。舊流程用兩家模型各寫一份＋第三家盲評（A/B），才穩定；單模型單稿的版本常常只有 3 分水準。

## 三、要保留的行為（機械規則，不要重新發明）

- 結尾落在人生道理，並拋一個「人人有自己答案」的問題（實測最有留言的一支 397 則，只講道理的 8 則）。
- 爆點壓在後 20%，40–60% 再鉤一次，懸念留到最後，結尾回扣第一句。
- 對外發布一律人工點頭；只有本人明確說「發」才發布。
- 閘門分級：字幕與稿一致、音量、錯字（用拼音比對，不要用逐字轉寫比對，同音字會誤判）；單一句不過不要卡死整支片。
- 排程用平台原生排程，不要用「腳本叫醒 bot」那條路（舊流程靜默失敗的來源）。

## 四、驗證清單（動手前先確認）

- [ ] 直式 1080×1920 輸出、時長可控制在 60–150 秒
- [ ] 中文字幕斷句正確、不壓到畫面主體
- [ ] 台灣口音 TTS 可離線跑，一段 30 秒旁白在 3 分鐘內完成
- [ ] 免費素材來源的授權標示需求（Pexels／Pixabay 不要求署名，但不可轉售原始素材）
- [ ] 無 API key 的情況下能否只用本機模型跑完整條（舊流程的硬要求：不花錢）
- [ ] 產出一支片的實際工時（舊流程幾乎都花在畫面客製，模板化後應降到 20 分鐘內）

## 五、明確不採用

- 生成式人臉／虛擬主播：格式用不到，且 Meta／YouTube 要求標示擬真 AI 人物，冷啟動信任度打折。
- 付費影片生成模型（Seedance、Wan 等）：本階段不花錢。
- 全自動發布：對外發布是人為決策點，不自動化。

## 六、下一步

1. 先在本 fork 跑通一支片，不接任何自動化。
2. 把寫稿規則（爆點結構＋結尾提問）做成 prompt 範本進 repo。
3. 再接選題（同題爆款對標）與排程，一次只上一個平台。
